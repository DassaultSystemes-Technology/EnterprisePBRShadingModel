**Enterprise PBR Shading Model** **User Guide** Dassault Systèmes Version 2025X ![][license.png] Introduction ============ The Enterprise PBR Shading Model (DSPBR) is a material model for physically based rendering, supported by all renderers in the [Dassault Systèmes](http://3ds.com target="_blank") [3DEXPERIENCE Platform](https://www.3ds.com/3dexperience/ target="_blank"). Physically based rendering (PBR) means that we approximate the real-world appearance of a surface with a bidirectional scattering distribution function (BSDF). This function describes how light interacts with the surface, i.e. how the light is reflected into the environment or transmitted into the volume beneath the surface. Conceptually, the Enterprise PBR Shading Model is organized in different components that cover different aspects of a material. * The [_Base_](#parameters/basecomponent) component contains parameters common to most materials. * The [_Iridescence_](#parameters/iridescencecomponent) component adds parameters to simulate special effects of thin film. * The [_Sheen_](#parameters/sheencomponent) component simulates micro-fibers standing perpendicular to the surface causing back scattering. * The [_Flakes_](#parameters/flakescomponent) component provides parameters for special metallic flakes as typically used for car paint. * The [_Clearcoat_](#parameters/clearcoatcomponent) component offers parameters describing a coating of a material like the clear coat of a lacquer paint. * The [_Emission_](#parameters/emissioncomponent) component contains parameters for specifying light radiation properties of a surface. * The [_Volume_](#parameters/volumecomponent) component features parameters for describing the volumetric parameters of (fully or partially) transparent materials. An overview of how these components are structured within the model can be found in the official [DSPBR specification](https://dassaultsystemes-technology.github.io/EnterprisePBRShadingModel/spec-2025x.md.html#components target="_blank"). It explains how the components are layered, interact and collectively affect the final appearance. Parameters ========== Although the Enterprise PBR Shading Model offers a large number of parameters, only a few of them are needed for most materials. This guide will walk you through all the parameters. ![Figure [parameter-overview]: Parameter overview[^parameter_range]](img/user_guide_material_chart.png) Base Component -------------- The _Base_ component of the Enterprise PBR Shading Model describes the most fundamental and most common visual parameters of real-world materials. The parameters of this component enable modeling the appearance of a large number of materials, both dielectrics (transparent and opaque) and conductors. ### Albedo _Albedo_ defines the overall color of the material. It takes an RGB value in the range [0, 1] as a constant or from a texture and applies it to the material. ![Figure [albedo]: Various Albedo colors and textured Albedo (most right sphere)](img/user_guide_albedo_color.png) !!! Tip: Make sure that an _Albedo_ texture does not include any lighting effects like shadows or specular highlights, because these effects are simulated by the rendering algorithm. !!! Note: A list of albedo values for typical materials can be found in the database of physically based values for CG artists [#PBRdb] or the documentation of the Unreal Engine 4 [#UE4]. ### Metallic The _Metallic_ parameter describes the metallic-ness of the surface. A value of 0.0 denotes a non-metallic or dielectric surface, a value of 1.0 is used for a metallic surface. Values in between can be used to linearly blend between the two models, for example for rusty metal. !!! Tip: Non-metals are 0 - metals are 1 This is usually a binary decision, a pure material can either be dielectric or metallic. Only for layering, e.g. dust onto metal, this parameter is between 0 and 1. ![Figure [metallic]: Metallic 0 to 1](img/user_guide_metallic.png) ### Roughness _Roughness_ describes the microscopic roughness of the surface. Smooth and polished surfaces have a low roughness value, rough surfaces have a high value. A perfect mirror has a value of 0. ![Figure [roughness]: Roughness 0 to 1. Non-metal (top row) and metal (bottom row).](img/user_guide_roughness.png) ### Anisotropy _Anisotropy_ controls the aspect ratio of the specular highlight. This is useful for, e.g. brushed metal, where the mirror-like microfacets on the surface are all oriented into the same direction, resulting in a long and narrow highlight. A value of 0.0 disables anisotropy, a value of 1.0 sets it to the maximum. ![Figure [anisotropy]: Anisotropy value 0 to 1](img/user_guide_anisotropy.png) The microfacets on the surface are oriented in a certain direction. This direction is initially given by the texture coordinates of the mesh, but can additionally be rotated with the _Anisotropy Rotation_ parameter, effectively rotating the specular highlight. A value of 0.0 corresponds to a 0° rotation, a value of 1.0 rotates 360°. ![Figure [anisotropy_rotation]: Anisotropy rotation value 0 to 0.5 (0° - 180°)](img/user_guide_anisotropy_rotation.png) !!! WARNING: Anisotropy needs texture coordinates The orientation of the highlight is based on the tangent space. That means that the surface needs proper texture coordinates from which the tangent space is computed. ![Figure [anisotropy_uv-mapping]: Anisotropy without (left) and with texture mapping coordinates (right)](img/user_guide_anisotropy_uv-mapping.png) !!! Note: No textures were used in Figure [anisotropy_uv-mapping] above, but only radial UV mapping was applied (right cylinder). ### Normal Map A _Normal Map_ describes the macroscopic structure of the surface in terms of the normal direction of the tangent space. This allows to add details like small bumps and dents without using more polygons. The normal direction is encoded as an RGB value in a texture, where the default normal [0,0,1] is mapped to the color [128,128,255]. ![Figure [Normal-mapping]: Sphere without normal mapping (left), a normal map texture (middle) and applied to the sphere (right)](img/user_guide_normal_texture.png) !!! WARNING: Mapping RGB values to vectors There is no universal standard for mapping 8‑bit RGB texture values in the range [0, 255] to floating‑point values in the range [‑1.0, 1.0]. Some systems use a convention where an 8‑bit value of 1 maps to ‑1.0, 128 maps to 0.0, and 255 maps to 1.0, leaving the value 0 effectively unused. Be careful when using normal maps from external sources, as they may rely on a different encoding scheme. !!! Tip: Coordinate system convention If bumps appear to sink into the surface instead of protruding, try inverting the green channel of the normal map texture. This often resolves mismatches between different normal map conventions, such as those used by OpenGL and DirectX. !!! Note The Normal Map of the _Base_ does not influence the [_Clearcoat_](#clearcoatcomponent) shading, but the [_Thin Film_](#thinfilm). ### Transparency _Transparency_ controls the transparency of the surface. An opaque surface has a transparency of 0.0, a transparent surface like glass or water has a transparency of 1.0. Values in between blend between the two models and may occasionally be useful for hybrid surfaces like dirty glass. ![Figure [transparency]: (Thin) Transparency value 0 to 1](img/user_guide_transparency.png) !!! Tip: Volume effects need a transparent or translucent surface For the [_Volume_](#parameters/volumecomponent) component features to have any effect, light must be able to enter the surface. This only happens when _Transparency_ or _Translucency_ is set to value greater than zero. !!!Note: Transparency vs. Opacity There is a difference between Transparency and Opacity. While Transparency changes the way light interacts with the surface, Opacity basically removes light surface interaction. See Figure [cutout]. ### Translucency _Translucency_ controls the amount of light that diffusely scatters through a surface. ![Figure [translucency]: Translucency value 0 to 1.](img/user_guide_translucency.png) It is most suitable for single-sided objects to simulate light penetrating the surface and illuminating the back side without actually being transparent. e.g. a sheet of paper or leaves. It also works with thick objects to give the impression of some light shining through the surface, e.g. porcelain (see Figure [translucency-color]). ![Figure [translucency-samples]: A sheet of paper (left). Blades of grass (right).](img/user_guide_translucency_examples.png) !!! Note: _Transparency_ overwrites _Translucency_ When _Transparency_ is used in combination with _Translucency_, the transparency effect overrides the translucency effect. !!! Tip: Combine _Translucency_ with Subsurface Scattering As _Translucency_ also allows light to penetrate the surface, it can be used in combination with volume properties like [_Subsurface Scattering_](#subsurfacescattering). !!! Tip: Use _Translucency_ for rough scattering _Translucency_ surface scattering is energy preserving and will not get darker with increasing [_Roughness_](#parameters/basecomponent/roughness). See Figure [sss_translucency_vs_transparency]. ### Translucency Color The _Translucency Color_ specifies the color after the scattering event. ![Figure [translucency-color]: Translucency Color changing from Albedo color (blue) to a reddish tint.](img/user_guide_translucency_color.png) ![Figure [translucency-color-samples]: Leaves of a plant with an orange Translucency (left). A porcelain tea cup with a bright beige Translucency Color (right).](img/user_guide_translucency_color_examples.png) !!! Tip: Surface vs. Volume scattering Translucency, in combination with [_Thin Walled_](#parameters/volumecomponent/thinwalled), can also be used for thick objects to simulate a [_Subsurface Scattering_](#subsurfacescattering) like effect without the costly calculation of evaluating light scattering at particles in an actual volume. ![Figure [translucency-vs_sss]: A porcelain tea cup with only _Translucency_ (middle) renders[^render_performance] over 20x faster than with actual _Subsurface Scattering_ (right). However, the result is still much more convincing than a shading without any scattering (left).](img/user_guide_translucency_vs_sss.png) ### Specular The _Specular_ parameter scales the amount of specular reflection on non-metallic surfaces. It has no effect on metals. ![Figure [specular]: Specular value 0 to 1](img/user_guide_specular_value.png) !!! Tip: Everything is shiny [#Hab10] Every surface in the real-world has a specular contribution, there are no pure diffuse surfaces. Therefore, there is usually no reason to touch this parameter, even for cardboard, cloth or concrete. To model mostly-diffuse materials, just make them rough. For pure diffuse materials, maybe for simple visualizations in engineering or high-performance preview renderings, this parameter can be set to zero to completely disable the microfacet-based reflection component. !!! Warning: Physically based Fresnel reflection Even though we consider the [_Index of Refraction_](#indexofrefraction) (IoR) a [_Volume_](#parameters/volumecomponent) parameter, it also affects specular surface reflection. It is used in the Fresnel equations, which are fundamental to our model for calculating physically plausible reflections. (See Figure [Index_of_Reflection]) ### Specular Tint _Specular Tint_ is an additional color parameter that tints the specular reflection of non-metallic surfaces. At grazing angles, the reflection still blends to a white _Specular Tint_. The parameter has no effect on metals. !!! ERROR: Possibly not physically plausible Be careful with this parameter! Setting it to anything but white is not physically plausible and can easily lead to unexpected behavior. However, certain non-photorealistic art styles may require this kind of flexibility. Iridescence Component --------------------- Iridescence (also known as goniochromism) is the phenomenon of gradual color shifts as the angle of view or the angle of illumination changes. Iridescence is caused by wave interference of light in micro structures (e.g. butterfly wings) or thin films (e.g. oil stains or soap bubbles). ### Thin Film An optical effect where light waves reflected by the upper and lower boundaries of a very thin transparent layer (film) interfere with each other, producing colorful patterns that depend on the light's wavelength, the film's thickness and its index of refraction (IoR). Specifies the intensity of the visible thin-film effect (see Figure [Iridescence_ThinFilm_amount] below). ![Figure [Iridescence_ThinFilm_amount]: _Thin Film_ amount 0 to 1](img/user_guide_irridescence_thinfilm_amount.png) ### Thin Film Thickness Specifies the thickness of the thin film in micrometers in the range [0, 1] µm. The _Thin Film Thickness_ in combination with the [_Thin Film IoR_](#parameters/iridescencecomponent/thinfilmior) influences the color shift based on the light's wavelength (see Figure [Iridescence_ThinFilm_IoR]). ![Figure [Iridescence_ThinFilm_thickness]: _Thin Film_ Thickness 0 to 1](img/user_guide_irridescence_thinfilm_thickness.png) !!! Note: The parameter range [0, 1] equals to 0 - 1000 nanometer (nm). This is sufficient, as only within such thickness a significant shift within the visible wavelength spectrum range of ~380nm - 750nm occurs. !!! Tip: Texture it! Typically, this parameter is textured to achieve varying thicknesses which result in common patterns of changing colors. See Figure [Iridescence_ThinFilm_thickness_textured] & Figure [Iridescence_ThinFilm_thickness_gears_textured] for examples with and without texture usage. ![Figure [Iridescence_ThinFilm_thickness_textured]: Without texture (left), Thickness texture (middle) and with texture (right).](img/user_guide_irridescence_thinfilm_thickness_texture.png) ![Figure [Iridescence_ThinFilm_thickness_gears_textured]: Without texture (left), Thickness texture (middle) and with texture (right).](img/user_guide_irridescence_thinfilm_thickness_gears_texture.png) !!! Tip: Minimum/Maximum Implementations may expose a value range for _Thin Film Thickness_ that allows to adjust the minimum and maximum of the parameter. This is especially useful for textured _Thin Film Thickness_ as it enables to specify which physical thicknesses the minimum (black) and maximum (white) pixel values represent. ![Figure [Iridescence_ThinFilm_thickness_range]: Thickness min. 140nm / max. 250nm (left), min. 200nm / max. 500nm (middle) and min. 100nm / max. 900nm (right).](img/user_guide_irridescence_thinfilm_thickness_texture_range.png) ### Thin Film IoR This parameter specifies the Index of Refraction (IoR) of the Thin Film. It affects the intensity of the color gradient, its position and repetition. The "rainbow effect" occurs in a more condensed range with higher IoR than with lower (see Figure [Iridescence_ThinFilm_ior] below). ![Figure [Iridescence_ThinFilm_ior]: Thin Film IoR 1.2 - 2.4](img/user_guide_irridescence_thinfilm_ior.png) !!! Warning: Depends on the Base The visibility of a _Thin Film_ highly depends on the properties of the [_Base_](#basecomponent) component. Most influential are the [_Albedo Color_](#parameters/basecomponent/Albedo) brightness and the [_Index of Refraction_](#indexofrefraction), responsible for the surface reflectivity. The darker the [_Albedo_](#parameters/basecomponent/Albedo) the more visible the Thin Film effect (see Figure [Iridescence_ThinFilm_albedo_intensity]). With an [_Index of Refraction_](#indexofrefraction) close to the [_Thin Film IoR_](#thinfilmior), the effect is less obvious as there is not much shift in visible wavelengths. The larger the difference between [_Index of Refraction_](#indexofrefraction) and [_Thin Film IoR_](#thinfilmior) the more intense the colors of the effect (see Figure [Iridescence_ThinFilm_ior_difference]). ![Figure [Iridescence_ThinFilm_albedo_intensity]: Base material _Albedo_ value 0.7 (left) and 0.4 (right)](img/user_guide_irridescence_thinfilm_albedo_intensity.png) ![Figure [Iridescence_ThinFilm_ior_difference]: Base material IoR 1.5 & Thin Film IoR 1.6 (left) and base material IoR 1.45 & Thin Film IoR 2.0 (right)](img/user_guide_irridescence_thinfilm_ior_difference.png) Sheen Component --------------------- Some fabrics like velvet show a significant amount of rim lighting (or sheen), resulting from both forward and backward scattering. This comes from tiny fibers standing straight up on the surface. ### Sheen Color The _Sheen Color_ controls the color as well as the intensity of the effect, based on its brightness. Black (no sheen) to white (maximum sheen). ![Figure [Sheen-color]: Black Sheen Color (most left) and full Sheen Color intensity (most right) at Sheen Roughness of 0.5.](img/user_guide_sheen_color.png) ### Sheen Roughness The _Sheen Roughness_ controls the angular spread of the sheen effect. Sheen is strongest at grazing view angles and fades toward normal (front‑facing) view angles. Lower Sheen Roughness keeps the sheen concentrated near grazing angles; higher Sheen Roughness spreads the effect so it remains visible over a wider range of incident/view angles. ![Figure [Sheen-roughness]: Sheen Roughness 0 to 1](img/user_guide_sheen_roughness.png) !!! Note: Sheen placement Sheen is layered above the [_Base_](#basecomponent) and [_Iridescence_](#iridescencecomponent) layer, but below [_Flakes_](#flakescomponent) & [_Clearcoat_](#clearcoatcomponent). See [Components-diagram](https://dassaultsystemes-technology.github.io/EnterprisePBRShadingModel/spec-2025x.md.html#components target="_blank") of the Enterprise PBR Shading Model. Flakes Component ---------------- _Flakes_ is an additional layer right below [_Clearcoat_](#clearcoatcomponent), above [_Base_](#basecomponent), [_Iridescence_](#iridescencecomponent) and [_Sheen_](#sheen). Flakes simulate small metallic particles which are typically used for metallic car paints (see Figure [Flakes-CarPaint]), but can also be used to simulate any kind of glittering particles on a surface (e.g. snowflakes, glitter, mineral traces). ![Figure [Flakes-CarPaint]: Metallic flakes car paint.](img/user_guide_flakes_carpaint.png) ### Coverage Specifies, in percentage, how much of the surface is covered by flakes. Areas of low coverage reveal more of the underlying layers (see Figure [Flakes-coverage] below). ![Figure [Flakes-coverage]: Flakes Coverage 0 to 1](img/user_guide_flakes_coverage.png) ### Flakes Color Specifies the overall color of the _Flakes_. ![Figure [Flakes-color]: Textured Flakes Color](img/user_guide_flakes_color_textured.png) ### Flakes Size Specifies the diameter of the flakes in millimeters. ![Figure [Flakes-size]: Flakes Diameter 0 to 2 mm (20 cm ⌀ sample sphere)](img/user_guide_flakes_size.png) !!! Tip For metallic car paint materials, flakes typically have a diameter in the range of 0.01 - 0.05 mm. ### Flakes Roughness Specifies the overall perceived roughness of the flakes. ![Figure [Flakes-roughness]: Flakes Roughness 0 to 1](img/user_guide_flakes_roughness.png) !!! TIP Good Flakes visibility A certain roughness of flakes is essential to get a typical differentiation of individual flakes. E.g. 0.3 - 0.4 for a common metallic car paint look. ### Flip/Flop The so-called Flip/Flop effect provides a view-angle-dependent appearance of a second (Flakes) _Flop Color_. This parameter specifies the amount of the _Flop Color_ blended with the general _Flakes Color_ (flip). This color is visible if the surface orientation is perpendicular to the viewing direction. Both colors blend in a Fresnel like behavior. ![Figure [Flakes-flip-flop]: Flakes Flop effect 0 to 1](img/user_guide_flakes_flop.png) !!! Note A Flip/Flop amount of 1 does not completely replace the general _Flakes Color_, but still shows it at the very grazing angles (see Figure [Flakes-flip-flop]). ### Flop Color Specifies the flop color of the _Flip/Flop_ effect (see Figure [Flakes-CarPaint-Flop] below). ![Figure [Flakes-CarPaint-Flop]: Metallic flakes car paint flip/flop.](img/user_guide_flakes_carpaint_flipflop.png) Clearcoat Component ------------------- A clear coat is an additional monochromatic specular reflection layer on top of all other layers (see [component structure](https://dassaultsystemes-technology.github.io/EnterprisePBRShadingModel/spec-2025x.md.html#components target="_blank")). It is enabled if the _Clearcoat_ parameter is not zero. Its IoR is fixed to 1.5 and its color to white, to provide the most common reflection behavior. The _Clearcoat_ is typically used as the final layer of car paint lacquers, but also in combination with other base layer configurations. For example, on top of rough metal or wood. See Figure [Clear-Coat-Examples] & Figure [Clearcoat_Normal] below. ![Figure [Clear-Coat-Examples]: Rough Metal without (left) & with Clearcoat (right).](img/user_guide_clearcoat_examples.png) ### Clearcoat Roughness With the additional _Clearcoat Roughness_, "frosted" or satinated coating can be simulate. ![Figure [Clearcoat_Roughness]: Plain lacquer paint without (left), with 25% (middle) and 50% Clearcoat Roughness (right).](img/user_guide_clearcoat_roughness.png) ### Clearcoat Normal The _Clearcoat_ layer can have a separate normal map, which works the same as the [_Normal Map_](#normalmap) of the [Base](#basecomponent) layer. ![Figure [Clearcoat_Normal]: Wood base material without (left), with Clearcoat (middle) and with Clearcoat Normal (right).](img/user_guide_clearcoat_normal.png) !!! Note The Clearcoat Normal does not influence the _Base_ but only the _Clearcoat_ shading. Cut-Out Component ------------------- _Cut-out_ acts like an alpha channel on geometry. It is typically a texture which defines holes in single-sided surfaces, making it possible to simulate highly-detailed geometry boundaries without additional polygons. !!! Tip: Cut-out (0) or not (1). This usually should be a binary decision. If a surface has a hole, set cut-out opacity 0. If not, set it to 1. Values in between can be used to smooth the edges. Use [_Transparency_](#parameters/basecomponent/transparency) if the surface is semi-transparent, e.g. for glass or water. ![Figure [cutout-geometry]: Cut-out mask texture (left) applied to a sphere (right). Note that cut away areas in the texture are exactly 0 (black), remaining regions are exactly 1 (white). Values in between are used for anti-aliasing at edges.](img/user_guide_cutout_geometry.png) !!! Note: Cut-out or Opacity Some applications might name this parameter _Opacity_ or even _Alpha_, which is effectively the same. It is important to distinguish between [_Transparency_](#parameters/basecomponent/transparency) and _Cut-Out_. [_Transparency_](#parameters/basecomponent/transparency) is a view-dependent effect that blends between reflection and transmission based on a Fresnel term. _Cut-Out_ is not view-dependent. It is the amount to which the surface does not exist. ![Figure [cutout]: Transparency (top) 0 to 1 and Cut-Out 1 to 0 (bottom). Note that while the sphere with cut-out completely vanishes, the transparent sphere is still reflecting.](img/user_guide_cutout.png) !!! Tip: From Albedo texture alpha channel It is a common industry practice to provide the cut-out via the Alpha channel of the [_Albedo_](#parameters/basecomponent/Albedo) color texture. !!! ERROR: Cut-out to hide objects Using a cut-out parameter without a texture and setting it to 0 to hide objects is strongly discouraged, especially in a raytracing context. This approach can make material evaluation inefficient and may introduce visual artifacts (for example, when another object occupies the same space). A better solution is to remove the geometry from the scene entirely. The same performance implication applies if this parameter is animated to fade an object in or out of view. Displacement Component ---------------------- _Displacement_ uses a texture, e.g. a vector map, to change the positions of a surface point in 3D space. It enables the displacement of arbitrary 3D shapes (e.g. a mouth from a plane surface, see Figure [vector-displacement]). In contrast to a simple [Normal Map](#normalmap), which only creates the illusion of macroscopic surface unevenness by altering the shading normal, displacement actually modifies the underlying mesh. This provides all the benefits of real geometry, such as correct self-shadowing and indirect illumination (depending on the renderer). A vector displacement map encodes a displacement vector (direction and magnitude) for each point on the surface. The renderer interprets this vector in a specific space (commonly tangent, object, or world space) and offsets the surface position accordingly, rather than displacing only along the surface normal. Depending on the implementation, the RGB channels represent the X, Y, and Z components of this vector. Values can be positive or negative and are not limited to the 0–1 range. ![Figure [vector-displacement]: Vector map (left) applied to a plane (right).](img/user_guide_displacement.png) !!! WARNING: Vector displacement encodings differ between tools Vector displacement maps are not standardized. Different applications and renderers can use different coordinate spaces and channel conventions for the XYZ components. As a result, a vector displacement map generated in one tool may not displace geometry correctly in another. If the directions appear wrong (e.g., features are “inside out” or shifted sideways), you may need to adapt the map by remapping or swapping color channels, inverting one or more channels, or converting between coordinate spaces, depending on what the target renderer expects. If the integrating application does not provide such conversion options, an external image editor or utility must be used. The higher the triangle density of the geometry mesh, the more details of the displacement map can be seen. ![Figure [displacement-subdivision]: No additional subdivision applied (left). Increased mesh density (middle). Highly tessellated mesh (right).](img/user_guide_displacement_subdiv.png) Higher mesh density can be achieved via geometry modeling or automatic render-internal subdivision methods. !!! NOTE: Common grayscale height maps can be "converted" to vector maps by placing this information only in the blue channel of a RGB texture. This allows a displacement only in the surface normal direction. Depending on the integrating renderer the defined value of displacement direction can vary, also with supported bit depth. (e.g. 8 bit texture input could be defined as no displacement for a value of 128, 0 - 127 as negative, 129 - 255 as positive position shift) !!! WARNING: Normal map textures do not work as vector maps As normal maps have a different color encoding and are typically only in 8bit. With such input the direction, strength and accuracy of the displacement will not provide the intended result. A conversion from Normal to Height map (grayscale) and further to vector could be used (see Figure [displacement-heightmap] below). ![Figure [displacement-heightmap]: A Normal map and applied as such (left). The same Normal map converted to a grayscaled height map and further converted to a vector map used for displacement (right).](img/user_guide_normal_to_displacement.png) A [Normal Map](#normalmap) can still be applied on top of displaced surfaces to provide further details. ![Figure [displacement+bump]: Only height map displaced geometry (left) and additionally with _Normal_ mapping enhanced details (right).](img/user_guide_displacement+normal.png) Emission Component ------------------ The Enterprise PBR Shading Model contains an emissive component that turns surfaces into area lights. Light is emitted uniformly into the upper hemisphere of the surface with regard to the normal of each point. Apart from [Emission Color](#emissioncolor), emission parameters cannot be textured. The color and amount of emitted light is determined by three parameters, which are closely related to real-world specifications of emission properties (see Figure [light-bulb-label]). ![Figure [light-bulb-label]: Specification of light emission properties of a real light bulb.](img/user_guide_light_bulb_label.png) ### Emission Color The color of the emitted light (roughly: the spectral distribution of emitted power) is determined by _Emission Color_. Real-world light bulbs typically specify this in terms of color temperature. In Figure [light-bulb-label] the color temperature (called "Light Appearance") is 2700 K. !!! Note: It is up to the integrating application and renderer how this color is specified and in which format (RGB or spectral). A black body function could be used, allowing to directly enter color temperature values in Kelvin (K). ### Emission Value and Emission Mode The brightness of a light source can be specified as luminous power (the perceived power of visible light emitted by a light source; unit: lumens or lm) or as luminous emittance (the perceived power of visible light emitted per surface area of the light source; unit: lux). Figure [light-bulb-label] (above) specifies a brightness of 850 lumens, which translates into an _Emission Value_ of 850 and setting _Emission Mode_ to luminous power. Figure [emission-modes] (below) illustrates the two emission modes. ![Figure [emission-modes]: For both spheres the Emission Value is 1. Emission Mode is set to luminous power [lumens] (left) and luminous emittance [lux] (right). ](img/user_guide_emission_modes.png) In the left image of Figure [emission-modes] the spheres radiate the same amount of energy into the scene, but they are differently bright when looking at them directly. The energy is more condensed on the smaller sphere due to its smaller surface area.
In the right image they appear equally bright, but the amount of energy emitted from the large sphere is actually significantly higher due to its larger surface area. !!! Tip: Using suitable emission mode Specify luminous power (lumens) whenever finding real-world specifications and when using proxy surfaces as light emitters (e.g. for light bulbs often the glass surface surrounding the filament is set as emissive instead of the filament that actually emits light). Use luminous emittance (lux), if changing the size of a light source should impact the amount of energy it emits. ### Energy Normalization Emission color can modify the emission in two different ways: * When _Energy Normalization_ is disabled, darker emission colors lead to darker emission even if hue and saturation are kept constant. The quantity of emitted light is determined by [_Emission Mode_](#parameters/emissioncomponent/emissionvalueandemissionmode) and the multiplication of [_Emission Color_](#parameters/emissioncomponent/emissioncolor) and [_Emission Value_](#parameters/emissioncomponent/emissionvalueandemissionmode).
Example: [_Emission Color_](#parameters/emissioncomponent/emissioncolor) is set to 50% gray, [_Emission Value_](#parameters/emissioncomponent/emissionvalueandemissionmode) is set to 1 and [_Emission Mode_](#parameters/emissioncomponent/emissionvalueandemissionmode) to luminous power. As a result, the light source emits colorless light at 0.5 lm. * When _Energy Normalization_ is enabled, the quantity of emitted light is solely determined by the emission mode and the emission value. [_Emission Color_](#parameters/emissioncomponent/emissioncolor) only modifies the hue of the light. Example: [_Emission Color_](#parameters/emissioncomponent/emissioncolor) is set to 50% gray, [_Emission Value_](#parameters/emissioncomponent/emissionvalueandemissionmode) is set to 1 and [_Emission Mode_](#parameters/emissioncomponent/emissionvalueandemissionmode) to luminous power. As a result, the light source emits colorless light at 1 lm. ![Figure [energy-normalization]: For both images and spheres the Emissive Value is 1 and Emission Mode is luminous power (lumens). The left sphere has a dark gray and the right a white Emission Color. Without Energy Normalization (left image) the left sphere is darker as emission color influences intensity. With Energy Normalization (right image) they are equally bright as Emission Color is only considered chromatically.](img/user_guide_energy_normalization.png) !!! Tip: Using _Energy Normalization_ Use energy normalization to replicate real light bulbs whose emission characteristics are specified by luminous power and color temperature as in Figure [light-bulb-label]. It is not recommended to use energy normalization to tweak the intensity of mesh lights via the emission color. Disable it when [_Emission Color_](#parameters/emissioncomponent/emissioncolor) is textured. Volume Component -------------------- While the appearance of all other components is only depending on the shaded object's surface topology (e.g. reflectivity, sheen), the look of the _Volume Component_ depends on the light/matter interaction inside the enclosed volume (e.g. absorption, scattering) and at its boundaries (e.g. refraction). ### Thin Walled In case the material is transparent or translucent, this parameter configures what happens in the space enclosed by the geometry boundary (the volume). There are two options: * Either the geometry defines the boundary between the outside world and a volume, i.e. the geometry encloses a volume. In this case, set _Thin Walled_ to false and use the volume parameters to configure the behavior (e.g. attenuation, scattering) inside the volume. * Or the geometry defines an infinitely thin volume with surfaces on both sides. _Thin Walled_ has to be set to true and the volume parameters (except [Index of Refraction](#indexofrefraction)) do not have an effect. !!!Note: This parameter has no effect if the material is neither transparent nor translucent. ![Figure [thin-walled]: Thin walled active (left) and disabled, resulting in volumetric shading, (right).](img/user_guide_thin_walled.png) ![Figure [thin-walled-sketch]: A geometry (black line) defines a two-sided object with an infinitely thin volume inside (left) or defines a boundary between outside and inside (gray area) with an actual modeled thickness (right).](img/user_guide_thin_walled_sketch.png) !!! WARNING: Rasterizer renderers have only limited support for volumetric shading Due to their complexity, refraction, attenuation and subsurface scattering are only partially supported by rasterizers. Do not expect consistency across all renderers. !!! Tip: Thin Walled is faster Although raytracers support volumetric shading, thin walled objects are much faster to render. When concerned about render times, use _Thin Walled_ if possible. For example, planar window glass is often very well approximated with a thin walled material, as it is usually only a few millimeters thick and refractions are hardly noticeable. ### Index of Refraction The _Index of Refraction_ (IoR) is a measured physical number usually in the range between 1 and 2 that determines how much the path of light is bent, or refracted, when entering a material. Material | Index of Refraction -------------|-------------------- Air | 1.0 Ice | 1.31 Water | 1.33 Plastic | 1.49 Window glass | 1.52 Flint glass | 1.62 Sapphire | 1.77 Diamond | 2.42 ![Figure [ior]: Index of Refraction 1 to 2. Note that besides refraction also the reflectivity changes with increasing IoR.](img/user_guide_ior.png) !!! Warning: IoR - "Index of Reflection" The IoR also influences the ratio between reflected and transmitted light, calculated from the Fresnel equations. Therefore, changing the IoR also influences the angle-dependent reflectivity on non-metallic materials, even if their surface is not transparent or refractive (see Figure [Index_of_Reflection] below)! ![Figure [Index_of_Reflection]: IoR 1 to 2.](img/user_guide_ior_reflection.png) ### Abbe Number Enables a realistic simulation of the _Color Dispersion_ effect, which in reality is caused by the [_IoR_](#indexofrefraction) being wavelength-dependent. Therefore, different colors are slightly differently refracted, based on their wavelength (e.g. ~480 nm for blue, ~546 nm for green), which in turn leads to color shifts at high contrast edges in refraction (see Figure [Color-dispersion_refraction_abbe] & Figure [Color-dispersion_refraction_ior]) or with refractive caustics (see Figure [Color-dispersion_caustics]). The _Abbe Number_ specifies the amount of the color shift in combination with the [_IoR_](#indexofrefraction). The typical values range from ~ 20 to 80, where lower values lead to a stronger effect. Additional information about Abbe numbers and typical examples can be found in [Wikipedia](https://en.wikipedia.org/wiki/Abbe_number). A value of 0 disables color dispersion. ![Figure [Color-dispersion_refraction_abbe]: Colored refraction with low Abbe Number (left) and high Abbe Number (right).](img/user_guide_abbe_22-75_IoR-1.5.png) ![Figure [Color-dispersion_refraction_ior]: Colored refraction with low IoR (left) and high IoR (right).](img/user_guide_abbe_50_IoR_1.5-2.5.png) ![Figure [Color-dispersion_caustics]: Colorful caustics from a diamond (left) and typical rainbow result of a thin light beam through a prism (right).](img/user_guide_color_dispersion_caustics_examples.png) !!! WARNING: Potential performance impact Color Dispersion calculation requires a certain amount of spectral evaluation, which is more complex to compute and therefore commonly impacts rendering performance. !!! Warning: Brightness Clamping during rendering Activating color dispersion, using the _Abbe Number_, can lead to overall undesired color shifts (typically towards pink) in the respective material or resulting caustics, when brightness clamping is used by a renderer, which does not use a complementary method. ### Attenuation The volume beneath a surface may contain small particles that absorb or scatter the light. Depending on the density of the particles, more light is absorbed or scattered. These particle-light interactions are wavelength-dependent and may therefore result in a colored appearance. The wavelength-dependent density of particles in the medium is controlled by the parameters [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor) and [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance). They define the remaining energy in terms of a color after a ray of white light traveled a certain distance through the volume. If [_Subsurface Scattering_](#subsurfacescattering) is disabled, all attenuation is solely based on absorption. If enabled, also scattering causes some attenuation. !!! Note: Attenuation has no effect on [_Thin Walled_](#parameters/volumecomponent/thinwalled) materials, as an infinitely thin surface does not absorb light. !!! Tip: To disable attenuation, set the _Attenuation Color_ to white, so that no light gets absorbed. #### Attenuation Color The color after white light traveled through a volume over the length of the [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance) (see Figure [Attenuation_distance]). !!! Tip: _Albedo Color_ and _Attenuation Color_ are not the same When [_Transparency_](#parameters/basecomponent/transparency) is 1, it seems like there are two options to control the color of glass: [_Albedo_](#parameters/basecomponent/Albedo) and _Attenuation Color_. However, there is a subtle difference: [_Albedo_](#parameters/basecomponent/Albedo) controls the absorption when the light enters the volume. _Attenuation Color_ determines what happens inside the volume (taking the distance the light travels into account). See Figure [Transparent_thick_object_color] below for comparison. As a rule of thumb: If an object is thin walled, set its color with the [_Albedo_](#parameters/basecomponent/Albedo) parameter. If it is volumetric, use _Attenuation Color_ and [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance) and set [_Albedo_](#parameters/basecomponent/Albedo) to white. The [_Albedo Color_](#parameters/basecomponent/Albedo) works like a filter for the incoming light through the surface before interacting with the _Volume_ below. The color of transparent volumetric objects is realistically defined by its volume properties rather than just its surface. E.g. water, solid colored glass (see Figure [Attenuation_vs_Albedo] below). ![Figure [Transparent_thick_object_color]: Object color defined by blue Albedo & white Attenuation Color (left) and object color defined by blue Attenuation Color & white Albedo (right). Notice how the intensity of the color changes at different object thickness and total internal reflection within the right glass bunny.](img/user_guide_attenuation_vs_albedo.png) ![Figure [Attenuation_vs_Albedo]: Comparison to a real world example: A photo (left), Albedo Color (middle) vs. Attenuation Color (right) used to tint the glass.](img/user_guide_attenuation_vs_albedo_glasses.png) !!! WARNING: Avoid absolute values (0.0 or 1.0) for any color channel Pure black _Attenuation Color_ makes the object opaque (full energy loss inside the volume due to attenuation) and pure white disables attenuation. In both cases, [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance) has no effect. If only some color channels have "pure" values (i.e. 0 or 1), the result may be unexpected or just unrealistic (see Figure [Attenuation_color_realistic]). ![Figure [Attenuation_color_realistic]: An orange Attenuation color specified as RGB values [1.0, 0.5, 0.0] (left) and more realistic with [0.97, 0.5, 0.03] (right).](img/user_guide_attenuation_color_absolute_vs_realistic.png) A spectral renderer might still show more reasonable results due to color up-sampling into spectra which provides more information beyond the 0 - 1 limitation of common RGB rendering (see Figure [Attenuation_color_upsampled]). ![Figure [Attenuation_color_upsampled]: The same orange Attenuation color values as in Figure [Attenuation_color_realistic], but rendered in spectral mode.](img/user_guide_attenuation_color_absolute_vs_realistic_spectral.png) #### Attenuation Distance The distance white light needs to travel through a volume of an object until the attenuation results in the specified [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor) (see Figure [Attenuation_object_thickness] & Figure [Attenuation_distance]). !!! Tip: To disable attenuation, set the _Attenuation Distance_ to a very high value, much larger than the actual maximum thickness of the geometry the material is assigned to. ![Figure [Attenuation_object_thickness]: Various object thickness in relation to constant [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor) & Distance: higher (left), same (middle) and lower (right).](img/user_guide_attenuation_object_thickness.png) ![Figure [Attenuation_distance]: Various Attenuation Distance values in relation to constant object thickness and [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor): lower (left), same (middle) and higher (right).](img/user_guide_attenuation_distance.png) ### Subsurface Scattering Subsurface scattering (SSS) models scattering of light inside a volume. While traveling through the medium, light rays may not only be absorbed when hitting a particle ([_Attenuation_](#parameters/volumecomponent/attenuation)), but also scattered into some direction, eventually leaving the surface at another point. !!! Tip: Subsurface scattering needs attenuation [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor) and [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance) describe the density of the medium, i.e. the mean free path length after which a particle is hit. If either the distance is too high, or the color is set to white, no particle will be hit, thus no scattering will occur. For very short attenuation distances, the overall appearance of an object with subsurface scattering is similar to a pure diffuse object. Utilize this to find good parameters for subsurface scattering.
Start with white [_Albedo_](#parameters/basecomponent/Albedo), full [_Transparency_](#parameters/basecomponent/transparency), very small [_Attenuation Distance_](#parameters/volumecomponent/attenuation/attenuationdistance) and some grayish value for [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor). Any _Subsurface Color_ (except black) will now be similar to a pure diffuse object without SSS and the same color set as [_Albedo_](#parameters/basecomponent/Albedo) (see Figure [Subsurface-Scattering] below). ![Figure [Subsurface-Scattering]: Diffuse Albedo, no SSS (left) and white [_Albedo_](#parameters/basecomponent/Albedo) color with the same blue color for Subsurface Scattering (right).](img/user_guide_sss.png) !!! Tip: Use Translucency for rough Scattering In case of higher [_Roughness_](#parameters/basecomponent/roughness) values, [_Translucency_](#parameters/basecomponent/Translucency) can be used to let light through the surface enter the volume. [_Translucency_](#parameters/basecomponent/Translucency) is energy preserving and will not get darker with increasing [_Roughness_](#parameters/basecomponent/roughness). ![Figure [sss_translucency_vs_transparency]: Subsurface Scattering with Transparency (left) vs. Translucency (right). Notice the overall brighter appearance with Translucency.](img/user_guide_sss_transparency_vs_translucency.png) #### Subsurface Color The perceived color of an object after many scattering events (assuming a white _Albedo_ and non-colored attenuation) is determined by the _Subsurface Color_. A _Subsurface Color_ of black disables the effect. The brighter the color the stronger the scattering. ![Figure [Subsurface-Color]: Blue Subsurface Color, Value intensities from 0 - 1, with Attenuation Color set to a medium gray.](img/user_guide_sss_color.png) !!! Tip: _Subsurface Color_ vs. _Attenuation Color_ For good single color Subsurface scattering results, it is recommended to use a gray [_Attenuation Color_](#parameters/volumecomponent/attenuation/attenuationcolor) and not the other way around. A colored attenuation may lead to unexpected results in a scattering context. See Figure [SSS_color-vs-Attenuation_color] below for comparison. ![Figure [SSS_color-vs-Attenuation_color]: Gray Attenuation & blue Subsurface Color (left), mixed blue Subsurface with green Attenuation Color (middle), green Attenuation & gray Subsurface Color (right).](img/user_guide_sss-color_vs_attenuation-color.png) #### Subsurface Anisotropy Specifies the direction of the scattering effect in a range from -1 to +1. Negative values result in a stronger backward scattering (back towards the camera) providing a denser look, while positive values result in more forward scattering (away from the camera) providing a more transparent appearance. A value of 0 gives a spherically uniform scattering behavior (see Figure [Subsurface-scattering-anisotropy]). ![Figure [Subsurface-scattering-anisotropy]: Subsurface Anisotropy, values -0.95 to 0.95](img/user_guide_sss_anisotropy.png)
